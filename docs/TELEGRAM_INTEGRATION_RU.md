# Концепция и архитектура Telegram на плате JC1060P470C (ESP32-P4)

Данный документ описывает варианты реализации и архитектуру работы мессенджера Telegram на аппаратной платформе **JC1060P470C** (ESP32-P4 + 32 МБ PSRAM + 16 МБ Flash + 7-дюймовый сенсорный экран 1024×600 JD9165 + тачскрин GT911 + Wi-Fi модуль ESP32-C6 / Ethernet IP101 + кодек ES8311).

---

## 1. Анализ ограничений и протоколов Telegram на микроконтроллерах

### 1.1. Почему не подходит официальная библиотека TDLib (MTProto 2.0)
* **Размер и зависимости:** Официальная библиотека `TDLib` написана на C++20, жестко завязана на SQLite, OpenSSL, zlib и тяжелые структуры данных. Её бинарный файл занимает от 25 до 50 МБ (физически превышает весь объём Flash-памяти платы 16 МБ).
* **Среда выполнения:** `TDLib` не портирована под FreeRTOS / ESP-IDF и требует полноценной операционной системы (Linux/Android/Windows/macOS).

### 1.2. Почему не подходит Telegram Web
* Веб-клиенты Telegram (*web.telegram.org K/Z*) представляют собой тяжёлые SPA-приложения на React/WebAssembly/WebWorkers.
* Для их рендеринга требуется браузерный движок уровня Google Chrome/WebKit с гигабайтами оперативной памяти и JIT-компилятором V8, что недостижимо для встраиваемых систем.

## 2. Реализуемые архитектурные сценарии

### Сценарий А. Автономный Telegram-терминал через Bot API (Рекомендуемый, без внешних серверов)

Плата работает напрямую с официальным облачным API Telegram (`api.telegram.org`) по протоколу HTTPS. Пользователь регистрирует личного бота в `@BotFather` и указывает его токен на плате.

```
+--------------------------------------------------------+
|                      Telegram Cloud                    |
|                   (api.telegram.org)                   |
+---------------------------+----------------------------+
                            ^
              HTTPS REST API| (порт 443 / mbedTLS)
                            v
+--------------------------------------------------------+
|             Плата JC1060P470C (ESP-IDF v6.1)           |
|                                                        |
|  [Wi-Fi C6 / Ethernet] -> [esp_http_client]            |
|                                  |                     |
|  [Фоновый опрос: getUpdates] <---+                     |
|  [Отправка текста: sendMessage]                        |
|  [Отправка фото: sendPhoto]                            |
|                                                        |
|  [Интерфейс 1024x600]:                                 |
|   - Список чатов (320 px)                              |
|   - Окно сообщений с пузырями (704 px)                 |
|   - Экранная клавиатура RU/EN с регистром              |
|                                                        |
|  [Периферия]:                                          |
|   - Звук оповещений через кодек ES8311                 |
|   - Фотоснимки с камеры OV02C10                        |
+--------------------------------------------------------+
```

#### Принцип работы:
1. **Приём сообщений (Long Polling):**
   * Задача FreeRTOS выполняет длительный HTTP-запрос:
     `GET https://api.telegram.org/bot<TOKEN>/getUpdates?offset=<ID>&timeout=30`
   * Сервер Telegram держит сокет открытым до 30 секунд. При появлении сообщения оно мгновенно возвращается в формате JSON.
   * Парсинг ответа выполняется через легковесную библиотеку `cJSON`.
2. **Отправка сообщений:**
   * Текстовое сообщение отправляется обычным POST-запросом:
     `POST https://api.telegram.org/bot<TOKEN>/sendMessage`
   * Аргументы: `chat_id` и `text` (в кодировке UTF-8).
3. **Звуковое оповещение:**
   * При получении входящего сообщения через аудиотракт ES8311 воспроизводится короткий PCM-сигнал уведомления.
4. **Отправка фото:**
   * Захват кадра с камеры OV02C10 в буфер JPEG и отправка методом `sendPhoto` через multipart/form-data.

### Сценарий Б. Доступ к личному аккаунту через локальный шлюз (Relay)

Если требуется читать личные каналы, группы и вести переписку со своего номера телефона:
1. На домашнем роутере, мини-ПК (Raspberry Pi) или сервере запускается микро-шлюз на Python (`Telethon` / `Pyrogram`) или Go (`gotd`).
2. Шлюз единожды авторизуется в Telegram по номеру телефона (MTProto).
3. Плата связывается со шлюзом по локальной сети через простой REST/WebSocket JSON протокол:
   * `GET /chats` — получить список диалогов;
   * `GET /messages?chat_id=...` — получить историю;
   * `POST /send` — отправить сообщение.
4. Вся криптография и синхронизация выполняются на шлюзе, а плата быстро и легко отрисовывает диалоги на экране.

## 3. Дизайн интерфейса под экран 1024×600 (JD9165)

Благодаря пропорциям 16:9 и диагонали 7 дюймов экран идеально делится на две рабочие области:

```
+------------------------+---------------------------------------------------+
| Панель статуса: Wi-Fi, IP, Часы, Громкость                                 |
+------------------------+---------------------------------------------------+
| Список диалогов (320px)| Шапка чата: Имя собеседника / Статус              |
|                        +---------------------------------------------------+
| [Иван Петров]          |                                                   |
| Привет! Как проект?    |  [Привет! Чем помочь?]                            |
| 11:42                  |                                                   |
|                        |                  [Проверяю плату на P4]           |
| [Рабочий чат]          |                                                   |
| Завтра релиз...        |  [Отлично, ждем результатов!]                     |
| 10:15                  |                                                   |
|                        +---------------------------------------------------+
| [Новости]              | [Строка ввода сообщения...]                 [ОТПР]|
| Вышла версия 6.1...    +---------------------------------------------------+
| 09:00                  | Экранная клавиатура (RU/EN, ЗАГЛ/стр, 123, ПРОБЕЛ)|
+------------------------+---------------------------------------------------+
```

### Основные элементы UI:
1. **Список диалогов (слева):**
   * Ширина 320 пикселей.
   * Аватар (или монограмма с первыми буквами имени), имя, фрагмент последнего сообщения, время, бейдж непрочитанных.
2. **Окно сообщений (справа):**
   * Ширина 704 пикселя.
   * Сообщения отображаются в виде скругленных блоков («пузырей»): входящие — темно-серые слева, исходящие — сине-акцентные справа.
   * Плавная вертикальная прокрутка жестом тача.
3. **Клавиатура ввода:**
   * Используется полноразмерная сенсорная клавиатура с русской и английской раскладками, цифрами, знаками препинания и кнопкой смены регистра (`ЗАГЛ`/`стр`).

## 4. Необходимые программные компоненты в проекте

1. **`main/telegram/tg_client.c`:**
   * Управление HTTP-клиентом `esp_http_client`.
   * Реализация цикла Long Polling `getUpdates`.
   * Формирование и отправка запросов `sendMessage`, `sendPhoto`.
2. **`main/telegram/tg_ui.c`:**
   * Отрисовка двухколоночного интерфейса.
   * Обработка тач-событий (выбор чата, прокрутка ленты сообщений, нажатия клавиш ввода).
3. **Интеграция с кодеком `ES8311`:**
   * Воспроизведение звука уведомления при событии `TG_EVENT_NEW_MESSAGE`.
4. **Интеграция с подсистемой камеры:**
   * Кнопка «Снимок» для быстрой отправки изображения в текущий чат.

---

## 5. Вывод

Реализация Telegram на плате **JC1060P470C** наиболее эффективна и надежна в виде автономного **Bot-клиента** прямо на ESP32-P4. Производительности процессора, 32 МБ оперативной памяти PSRAM и аппаратных возможностей 7-дюймового сенсорного экрана более чем достаточно для создания быстрого, отзывчивого и функционального настольного смарт-мессенджера.
