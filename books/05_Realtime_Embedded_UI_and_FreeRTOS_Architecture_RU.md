# Архитектура встраиваемых интерфейсов реального времени и FreeRTOS
## Паттерны проектирования GUI без зависаний для ESP32-P4 / ESP-IDF

---

## 1. Проблема монолитного графического цикла («Антипаттерн суперцикла»)
Во многих учебных примерах для Arduino и простых контроллеров код пишется в парадигме монолитного цикла:

```c
// ❌ АНТИПАТТЕРН: Всё в одной задаче FreeRTOS
void ui_task(void *arg) {
    while (1) {
        if (touch_detected()) {
            perform_action_and_network_calls(); // БЛОКИРОВКА НА 2-3 СЕКУНДЫ!
            redraw_screen();
        }
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
```

### Чем это опасно на ESP32-P4:
1. **Сетевой стек LwIP и Wi-Fi** работают асинхронно через SDIO с чипом ESP32-C6. Сетевые вызовы (`connect`, `recv`, DNS-резолв) могут «залипать» на секунды из-за помех эфира, повторных передач пакетов и TLS-рукопожатий.
2. **Аудиотракт (I2S, ES8311, кольцевой буфер)** требует синхронизации через мьютексы и деинициализацию драйверов.
3. Пока `browser_task` стоит в ожидании сокета или плеера, **дисплей 1024×600 не получает обновлений**, контроллер тача не опрашивается, а пользователь видит замершую картинку.

## 2. Архитектурный паттерн: Разделение UI-потока и воркеров (Producer-Consumer)

В профессиональных системах (LVGL, Android, Qt Embedded) задачи жестко разделены:

```
┌────────────────────────────────────────────────────────┐
│  High-Priority UI Task (browser_task, CPU0, Prio 5)    │
│  - Опрос тач-панели (каждые 16 мс)                     │
│  - Обработка жестов и кнопок                           │
│  - Отрисовка кадрового буфера (MIPI-DSI)               │
│  - Гарантированный отклик < 20 мс                      │
└───────────────────────────┬────────────────────────────┘
                            │
               xQueueSend() │ Асинхронное неблокирующее
               (команда)    │ сообщение (Zero-wait)
                            ▼
┌────────────────────────────────────────────────────────┐
│  Background Media Worker Task (media_task, CPU1, Prio 3)│
│  - Остановка старого потока                            │
│  - DNS и TCP/TLS подключение к Icecast                 │
│  - Буферизация MP3 чанков                              │
│  - Вызов колбэка обновления статуса (EVENT)            │
└────────────────────────────────────────────────────────┘
```

## 3. Паттерн «Optimistic UI» (Оптимистичный интерфейс)

Паттерн Optimistic UI — это стандарт современной разработки, когда интерфейс **не ждет подтверждения от сети или тяжелого сервиса, а мгновенно переключает экран в целевое состояние**:

### Алгоритм работы:
1. Пользователь коснулся карточки «Дорожное Радио».
2. **Шаг 1 (Мгновенно, t = 0..16 мс):**
   - Установить выбранную станцию: `s_radio_pending_idx = clicked_idx`.
   - Установить визуальный статус: `s_radio_status = STATUS_CONNECTING`.
   - Перерисовать карточку с ярко-голубой рамкой и пульсирующим текстом: `draw_screen(); app_lcd_flush();`.
   - Экран отреагировал мгновенно! Пользователь удовлетворен.
3. **Шаг 2 (В фоне):**
   - Отправить сообщение медиа-плееру.
   - Плеер не спеша закрывает старый сокет и открывает новый.
4. **Шаг 3 (По готовности потока):**
   - Плеер шлет событие `MEDIA_EVENT_PLAYING`.
   - Интерфейс меняет надпись «ПОДКЛЮЧЕНИЕ» на «В ЭФИРЕ».

## 4. Защита от дребезга и спама тачей (State Guarding)

Когда станция подключается (статус `CONNECTING`), повторные тапы по той же или другим станциям должны корректно фильтроваться:
- Повторный тап по той же станции — игнорируется (no-op).
- Тап по другой станции — ставит новую станцию в очередь, отменяя предыдущее подключение, либо блокируется с подсказкой *«Идет подключение...»*.
- Тап по кнопке «СТОП» — немедленно прерывает подключение и возвращает интерфейс в режим ожидания.

## 5. Профилирование и инструментация в ESP-IDF
Espressif ESP-IDF предоставляет встроенные инструменты для поиска зависаний UI:
1. **Application-Level Tracing (`esp_app_trace`)**: трассировка выполнения функций без влияния на тайминги.
2. **SEGGER SystemView**: визуализация переключения контекстов задач FreeRTOS, прерываний и времени ожидания мьютексов.
3. **Task Watchdog Timer (TWDT)**: автоматическое обнаружение зависших задач при превышении допустимого времени непрерывного исполнения.
