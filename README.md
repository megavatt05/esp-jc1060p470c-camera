# HMI станка намотки PON-кабеля на ESP32-P4 (плата JC1060P470C)

Ветка `feature/winder-hmi-485`: сенсорная панель управления намоточного станка
и управление частотным преобразователем **Easydrive Mini-S** по Modbus RTU /
RS-485. Измеритель длины **ИДМ-20** по требованию в этой сборке **выключен**
(`CONFIG_STANOK_USE_IDM20=n`) — код драйвера на месте, но PCNT-канал не
создаётся, пины A/B свободны, автомат останова по длине не срабатывает.

- **Плата:** GUITION JC1060P470C (_I_W / _Y), ESP32-P4 silicon rev 1.3, 32 МБ PSRAM @ 200 МГц
- **Дисплей:** 7″ IPS 1024×600, JD9165, MIPI-DSI 2 lanes 750 Мбит/с, DMA2D
- **Тач:** Goodix GT911 (I²C, mirror_x=1, mirror_y=1)
- **Фреймворк:** ESP-IDF v6.1.0, LVGL 9.5 + `esp_lvgl_port` (`swap_bytes = false`)
- **Шрифты:** LVGL 9, DejaVu с кириллицей (16/24/32) + цифровые 48/72/120

## 1. Пиновка по схеме платы V1.0

| Узел / сигнал | GPIO | Источник истины |
|---|---|---|
| Подсветка LCD | 23 | LEDC, 5 кГц, 10 бит |
| Сброс LCD | **0** | схема: GPIO0 → R47 |
| MIPI DSI PHY | LDO канал 3, 2500 мВ | включать до инициализации DSI |
| I²C (тач + ES8311) | SDA 7 / SCL 8 | порт 1, 400 кГц |
| GT911 Reset / Interrupt | 22 / 21 | адреса 0x5D и 0x14 |
| **RS-485 TX** | **26** | U8 MAX485: GPIO26 → R75 → DI |
| **RS-485 RX** | **27** | U8 RO → R70 → GPIO27 |
| RS-485 DE/RE | **нет в программном управлении** | /RE и /DE сшиты в EN, направление переключает автомат на 74LVC1G132 + Q3 (8550) |
| ИДМ-20 фаза A / B | 4 / 5 | зарезервированы, в сборке отключены |
| Кнопка BOOT | 35 | strapping 34..38 |

Занято и недоступно для станка: 9/10/11/12/13/48 (I²S аудио + PA), 21 (прерывание
тача), 22 (сброс тача), 23 (подсветка), 0 (сброс LCD), 31/50/51/52 (Ethernet RMII),
39..44 (microSD), 14..19/54 (ESP-Hosted SDIO слот 1 + сброс C6), 1/34..38 (strapping).

**Почему нельзя было GPIO2/3, как в README вендора.** Встроенный MAX485 сидит на
UART1 = GPIO26/27, и именно туда заведена гребёнка J5 (те же TX1/RX1 + 5V/GND).
GPIO27 при этом свободен, потому что сброс панели на этой плате — GPIO0, а не 27.
На случай другой ревизии платы в драйвере остаётся авто-пробирование пар TX/RX:
оно включено по умолчанию (`CONFIG_STANOK_RS485_AUTO_PINS=y`,
`CONFIG_STANOK_RS485_PIN_SCAN=y`) и выключается само, если в menuconfig задан
явный пин DE.

## 2. Протокол и карта регистров ПЧ

Modbus RTU, **9600 8E1** (в преобразователе P8.01 = 0x13), адрес ведомого 1.
Функции 03H / 06H / 10H, CRC-16/MODBUS (полином 0xA001, младший байт первым),
межкадровый зазор T3.5.

Полная карта — [`docs/VFD_REGISTERS.md`](docs/VFD_REGISTERS.md): все d-регистры,
биты слова состояния, слова `0x2000`, правило адреса и **все 185 параметров P0..PA**
с единицами, диапазонами, заводскими значениями и колонкой «что берёт эта панель».

| Регистр | Смысл |
|---|---|
| `0x2000` | слово управления: стоп `0x0001`, вперёд `0x001E`, назад `0x002E`, толчок `0x0013`/`0x0023`, сброс аварии `0x0031` |
| `0x2001` | уставка частоты, 0.01 Гц |
| `0x0D00..0x0D04` | d-00..d-04: выходная частота, уставка, ток (0.01 А), напряжение выхода (1 В), обороты |
| `0x0D06`, `0x0D0F` | линейная скорость и температуры радиатора/IGBT (0.1 °C) |
| `0x0D13..0x0D1B` | журнал d-19..d-21 и снапшот аварии d-22..d-27 |
| `0x0E00` | слово состояния: bit4 RUN, bit15 авария, bits8..14 номер Er |

Особенности привода, измеренные на живом устройстве (под них настроен драйвер):
- кадр чтения длиннее 5–6 регистров привод не тянет → читаем блоками ≤ 5;
- на битый кадр привод **не** отвечает ошибкой Modbus, он молчит → молчание = ошибка;
- запись на несуществующий адрес привод подтверждает эхом → эху не доверяем,
  подтверждение только по readback (слово состояния и d-01);
- задержка кадра 29–39 мс при 9600 8E1;
- 0 ошибок в 480 транзакциях подряд.

## 3. Что делает сборка отказоустойчивой

- Единственный владелец шины — задача `vfd_task` с очередью команд; из UI
  вызывается только `vfd_cmd_*` (асинхронно, без блокировок на тач-кнопке).
- Рамка ответа проверяется по длине, адресу, функции и CRC; 3 ретрая с
  backoff 40 мс.
- Подтверждение команды чтением: `0x0E00` (RUN/авария) и уставка `d-01`;
  если частота не сошлась — в лог «уставка не сошлась: записали X, привод показывает Y».
- Watchdog линии: нет честных ответов → принудительный СТОП и баннер
  «НЕТ СВЯЗИ С ПЧ | TX=GPIO.. RX=GPIO.. | битых N таймаутов M».
- Стоп при загрузке (первое, что делает драйвер — гонит привод в останов).
- Task watchdog на самой задаче шины (3 периода опроса + 8 с, panic).
- Тач-панель склонна к фантомным нажатиям, поэтому ПУСК — с подтверждением:
  первое касание взводит на 3 с («ПУСК? ЕЩЁ РАЗ»), второе запускает.
- Диагностика на экране настоящая: слово состояния, ErNN, температура радиатора,
  обороты, мощность, напряжение звена, счётчики кадров/команд/битых/таймаутов/ретраев.

## 4. Параметры преобразователя, которые нужно выставить руками

| Параметр | Значение | Зачем |
|---|---|---|
| P8.01 | `0x13` | 9600, 8E1 — иначе контроллера и привода не слышат друг друга |
| P8.02 | таймаут связи, например `2.0 с` | по нашему watchdog линия падает раньше, но привод сам должен уйти в аварию при обрыве связи |
| P0.04 / источник пуска | `2` (Modbus/comms) | пуск только по слову `0x2000` |
| P0.01 / источник уставки | `3` (comms) | частота только из `0x2001` |
| P0.07 | нижний предел частоты | помнит: при P0.07=10 Гц запрашиваемые 5 Гц поднимаются до 10 |
| Время торможения | разумно длинное (не минимальное) | иначе выбег не успевает скомпенсировать и длина врёт при включении ИДМ-20 |

## 5. Сборка и прошивка

```powershell
powershell -NoProfile -File C:/Users/megav/.espressif/hermes/idf.ps1 -Idf v6.1 -Dir <путь-к-репозиторию> -Task "set-target esp32p4"
powershell -NoProfile -File C:/Users/megav/.espressif/hermes/idf.ps1 -Idf v6.1 -Dir <путь-к-репозиторию> -Task "build"
powershell -NoProfile -File C:/Users/megav/.espressif/hermes/idf.ps1 -Idf v6.1 -Dir <путь-к-репозиторию> -Task "-p COM10 flash"
```

Пути в параметрах — только через `/` (PowerShell съедает обратные слэши).
Лог после перезагрузки: `serial-log.ps1 -Port COM10 -Seconds 16`.

Разделы: таблица на `0x10000`, приложение на `0x20000`, 4 МБ. Прошивка:
QIO 80 МГц, 16 МБ. Для P4 rev 1.3 обязательны `REV_LESS_V3` + 360 МГц — иначе
esptool не даёт прошить, а загрузка зацикливается на
`assert failed: esp_clk_init clk.c:105`.
