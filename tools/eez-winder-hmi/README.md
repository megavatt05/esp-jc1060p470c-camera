# WinderHMI — проект EEZ Studio 0.29 для пульта намотки PON

Проект `WinderHMI.eez-project` — это те же четыре экрана, что собраны в
SquareLine-версии (`../easydrive-hmi/gen_ui.py`), но отданные EEZ Studio.
Гарантия повторяемости: файл пишет `gen_eez.py`, все `objID` = `uuid5(ключ)`,
поэтому повторный запуск даёт побайтово тот же JSON.

Плата/панель: GUITION JC1060P470C (ESP32-P4), 1024x600 MIPI-DSI, LVGL 9,
частотник Easydrive по RS-485 (UART1, 9600 8E1).

## Разделение ответственности

EEZ владеет только геометрией, цветами, шрифтами и списком виджетов.
Движок Modbus остаётся единственным источником значений: `vars.c` и `actions.c`
в проект **не** генерируются (их нет в `settings.build.files`), их пишет
прошивка. Таким образом правка макета никогда не может «перезаписать» логику.

## Сборка

Каноническое место макета — `tools/eez-winder-hmi/` этого репозитория
(копия в `~/Downloads/eez-winder-hmi` — рабочая, содержимое идентично).

```
"C:/Users/megav/AppData/Local/Programs/eezstudio/EEZ Studio.exe" \
    --build-project "$PWD/tools/eez-winder-hmi/WinderHMI.eez-project"
```

Либо `python gen_eez.py` и затем та же команда. Результат — 11 файлов в
`generated/ui/` (`screens.h/c`, `vars.h`, `actions.h`, `fonts.h`, `styles.h/c`,
`images.h/c`, `ui.h/c`). `screens.c` ≈ 142 КБ, кириллица в литералах UTF-8.

## Что обязана предоставить прошивка

### Действия (объявлены в `actions.h`, EEZ сам навешивает их на CLICKED)

```c
void action_nav_main(lv_event_t *);   void action_nav_params(lv_event_t *);
void action_nav_alarm(lv_event_t *);  void action_nav_conn(lv_event_t *);
void action_btn_start(lv_event_t *);  void action_btn_stop(lv_event_t *);
void action_btn_jog(lv_event_t *);    void action_btn_rev(lv_event_t *);
void action_btn_fault_reset(lv_event_t *);
void action_sp_up(lv_event_t *);      void action_sp_dn(lv_event_t *);
void action_par_read(lv_event_t *);   void action_par_write(lv_event_t *);
void action_journal_read(lv_event_t *); void action_fault_reset(lv_event_t *);
void action_counters_reset(lv_event_t *);
```

В именах в проекте префикса `action_` быть не должно — EEZ добавляет его сам.

### Переменные (объявлены в `vars.h`, вызываются из `tick_screen_*` и из
встроенных обработчиков виджетов)

* целые: `sp_raw` (уставка, сырое число регистра 0x2001) и `par_channel`,
  `par_fmax`, `par_fmin`, `par_fbase`, `par_accel`, `par_decel`, `par_jog`;
* строковые `*_txt`: всё, что видит оператор (`freq_txt`, `state_txt`,
  `cur_txt`, `volt_txt`, `rpm_txt`, `sp_txt`, `link_txt`, `p_msg_txt`,
  `fault_*_txt`, `jrn0..2_txt`, `snap0..5_txt`, `c_*_txt`).

Форматирование чисел остаётся в прошивке: строковые переменные и есть то, что
рисует_label, а целые — только то, что крутит слайдер/спинбокт в сырых единицах
регистра.

### Три правила, иначе UI порвётся на глазах

1. `get_var_*_txt()` не имеет права вернуть `NULL` — генератор делает
   `strcmp(new_val, cur_val)`.
2. `get_var_par_*()` / `get_var_sp_raw()` должны вернуть **последнее значение,
   переданное в `set_var_*`** (теневая копия у прошивки). В `tick_screen_params`
   нет проверки `LV_STATE_EDITED`: если геттер вернёт значение из регистра, а
   оператор уже крутит спинбокт, тик будет его отвоевывать обратно.
3. `VALUE_CHANGED` у слайдера и спинбоктов явно действием не обвешан — EEZ
   навешивает встроенный `event_handler_cb_<экран>_<виджет>`, который вызывает
   `set_var_sp_raw` / `set_var_par_*`. Именно оттуда прошивка получает правку
   оператора (для слайдера — на каждое движение, дебаунс на стороне прошивки).

### Точки входа

`ui_init()` строит все четыре экрана и грузит ГЛАВНУЮ; `ui_tick()` опрашивает
текущий; `loadScreen(SCREEN_ID_PARAMS)` и т.п. переключает с
`LV_SCREEN_LOAD_ANIM_FADE_ON`, 150 мс. Каждый вызов из своей задачи обязан быть
под `lvgl_port_lock()/unlock()` — на этой панели это уже приводило к livelock
CPU0.

## Шрифты: внешний вид предоставляет прошивка

EEZ генерирует `fonts.h` с четырьмя `extern const lv_font_t`:
`ui_font_body16`, `ui_font_label20`, `ui_font_head26`, `ui_font_big56`
(и таблицу `fonts[]`, которая определена в `screens.c`).
Генератор **молча не пишет** `.c`-файлы шрифтов: `copyFontFiles()` работает
только в режиме выгрузки «buildFiles», а при `fontExportMode: "source"` создаёт
лишь extern-объявления. Так что линкует проект именно те четыре файла, что уже
есть в `../easydrive-hmi` (они собраны из `ofont.ru_Roboto.ttf`,
`-r 0x20-0x7F -r 0x401 -r 0x410-0x44F -r 0x451 -r 0xB0`) — при переносе в
прошивку их символы нужно переименовать в нижний регистр.

**Ловушка NTFS:** EEZ всегда приводит имя шрифта к нижнему регистру, поэтому
`ui_font_Body16.c` и `ui_font_body16.c` для Windows — один и тот же файл.
Именно поэтому шрифты в проекте названы `body16/label20/head26/big56`, а
`destinationFolder` вынесен в `generated\ui`, вне дерева `main/`.

## Экраны

| экран | содержимое |
|---|---|
| ГЛАВНАЯ | связь, выходная частота, состояние привода (0x0E00), ток/напряжение/обороты, уставка (слайдер 0..5000 = 0..50.00 Гц, ±50), ПУСК / СТОП / ТОЛЧОК / РЕВЕРС / СБРОС |
| ПАРАМЕТРЫ | 7 параметров P0.01/0.06/0.07/0.08/0.14/0.15, P2.19, ЧИТАТЬ / ЗАПИСАТЬ, сообщение |
| АВАРИИ | активная авария (код, имя, описание, время), журнал d-19..d-21, снапшоты d-22..d-27, ОБНОВИТЬ ЖУРНАЛ / СБРОС АВАРИИ |
| ЛИНИЯ | состояние, профиль драйвера, счётчики обмена, последняя команда и сбой, СБРОС СЧЁТЧИКОВ |

Нижняя навигация — 4 кнопки по 246x60 на полосе 1024x84 (y=516), чтобы попадание
не зависело от шума панели; верхняя — 1024x56.

## Размерность параметров (перепроверено по карте CV3100/MINI-S, 2026-10-21)

`digits`/`frac` в `PARAMS` = «сколько цифр всего» и «сколько после точки»; `frac`
обязан равняться количеству нулей в единице регистра, иначе число врёт в 10 или 100 раз:

| строка | регистр | единица | frac | как читается сырое слово |
|---|---|---|---|---|
| Канал задания | P0.01 = 0x0001 | целое 0..8 | 0 | 3 |
| Верхняя частота | P0.06 = 0x0006 | 0.01 Гц | 2 | 7000 -> 70.00 |
| Нижняя частота | P0.07 = 0x0007 | 0.01 Гц | 2 | 1000 -> 10.00 |
| Базовая частота | P0.08 = 0x0008 | 0.01 Гц | 2 | 5000 -> 50.00 |
| Время разгона | P0.14 = 0x000E | 0.1 × **единицы P3.09** | 1 | 104 -> 10.4 |
| Время торможения | P0.15 = 0x000F | то же | 1 | 200 -> 20.0 |
| Частота толчка | P2.19 = 0x0213 | 0.01 Гц | 2 | 1000 -> 10.00 |

Единицу времени выбирает **P3.09 = 0x0309** (0 = секунды, 1 = минуты, завод — минуты).
На стенде прочитан 0, значит разгон 10.4 с. Тот же шаг относится к P2.20/P2.21.

## Правка макета

Не редактируйте `WinderHMI.eez-project` руками и не правьте `generated/ui/*` —
при следующей сборке затрёт. Меняйте `gen_eez.py` (палитра, `PARAMS`, координаты
собраны там же, где в `gen_ui.py`), затем regenerate + build. Открыть в GUI для
нагляда: `EEZ Studio.exe WinderHMI.eez-project`.
